**Claim coverage**

- Claim 1 (permissions and tenant isolation) is covered by `tests/test_saved_reports_access.py`. It tests cross-tenant access, the foreign-vs-missing error oracle, confidentiality, role gates, revocation by demoted or unknown roles, payload tenant injection, and audit rows.
- Claim 2 (revocation keeps the snapshot and hash) is covered by `tests/test_saved_reports_snapshots.py`. The shipped code already keeps this claim, so these tests pass on it. Their value is the mutation evidence showing they catch snapshot edits, deletions and hash changes.
- Claim 3 (batch reports the truth) is covered by `tests/test_saved_reports_batch.py`. It checks that a partial or failed batch is not reported as complete and that `applied` equals the rows actually stored.
- `tests/test_dataset_regression.py` guards DatasetRegistry.
- `tests/_support.py` holds the shared fixtures.
- `test-plan.md` gives each test's claim, how it detects a false claim, its result on the shipped code, and the gaps.

**Gaps (in the plan)**

- No concurrency or conflicting-update tests. The service has no versioned update API, so there is no conflict path to test.
- Mid-session revocation is not tested. Role changes are modelled as a new `User` object, because the service has no session store.
- Duplicate submissions are checked only for snapshot integrity. The claims don't say whether a duplicate should be rejected.
